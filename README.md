# projectmanager v3.26.0

## v3.26.0：工作周日志、测试关联、项目排序和统一版本选择

1. 日志左侧历史列表去掉内容摘要与悬停预览，只显示日期和星期。按工作年 / 第几周分类，默认当前日志所在工作周；可筛选全部工作周。采用 ISO 8601 周号：周一至周日，第 1 周是包含 1 月 4 日的一周；跨年日期归属该周的工作年，例如 2025-12-31 属于 2026 年第 1 周。今日计划/实际两列、明日计划、唯一保存、右侧只读事项和旧历史记录继续保留。
2. 所有界面中日期时间的分隔 T 显示为空格，包括 Issue 创建时间、测试时间、版本记录时间、研发事项更新时间和日志保存时间。原数据库中的 ISO 时间保持兼容，不批量改写历史时间字段。
3. Issue 新增/编辑可下拉多选关联同项目测试，表格显示关联测试链接，点击进入对应测试编辑。服务端检查测试归属和存在性，关联失败不部分保存，修改其他字段不清空关联；测试 / Issue / 项目删除会清理关联。兼容已有 test_issues 表数据。
4. 软件版本表的 Branch 列由窄列扩展为至少 24ch，长分支名可换行，编辑输入框保持正常宽度。
5. 左侧主入口顺序为个人 Dashboard、每日日志、项目。项目列表可拖拽或使用上/下按钮调整顺序，保存到数据库，重启后保留；新项目追加到末尾。排序冲突会提示刷新，不覆盖其他页面新增项目。
6. 任务、子任务、Issue、测试统一使用软件版本下拉多选，列表可上下滚动，最新记录排在上方。新增记录默认选择当前项目最新添加的版本（最高记录 ID，不按版本号字符串猜测大小）；编辑记录保留原关联，编辑时未关联版本仍保持未选择，用户可取消或多选。
7. 测试新增/编辑窗口明确提供软件版本选项，与任务的选择方式一致。保留原测试步骤、环境、预期/实际结果和状态字段。帮助教程同步更新。

### 数据迁移与验证

启动自动为 projects 添加 sort_order 列，旧项目初始仍按 ID 顺序。Issue/测试关联复用已有 test_issues 表，不清除旧数据。日志归档 API 新增 work_years，原年月 years 数据保留以兼容旧客户端。项目顺序和关联随数据库备份一起保存。原工程及数据库保持不变；将数据副本与设置复制到新工程后运行 run_dev.bat 即可。

```text
python tools/check.py
```

可选真实浏览器检查：安装 playwright 后执行 `python tools/browser_smoke.py`，使用本机 Chrome 和临时数据库，覆盖项目排序、工作周、Issue 测试链接、最新版本默认、长列表滚动、宽 Branch 列及原业务。静态 HTML 加载模块，无 Node 构建依赖。结果见 VALIDATION.md。

## v3.23.0：任务自动排期、紧凑选择与明日计划

- 新建顶级任务默认从当前项目最后一个顶级任务截止日的次日开始，且不早于今天；新建子任务按同一父任务下的兄弟任务顺延，无兄弟任务时采用今天或父任务开始日的较晚值。手动修改日期仍可安排并行任务。
- 选择前置任务后自动预览日期：开始日期不早于所有前置任务最晚截止日的次日，顺延时保留原任务时长。前置任务按项目内 Task 编号升序排列，采用可展开的下拉多选。
- 保存时在同一数据库事务内校正排期。编辑前置日期、编辑依赖（含独立依赖 API）都会顺延受影响的后续任务；不修改其他项目的任务。
- 子任务超出父任务范围时自动扩大父任务开始/截止日期，并逐级更新祖先任务；父任务延期时较早的子任务同步顺延，并保留各自时长。范围只扩大，不因子任务缩短或删除而自动缩小。
- 保留自依赖、跨项目依赖和循环依赖校验。父子任务之间不能互为前置；间接依赖与层级构成无法满足的日期约束时明确提示并回滚整个修改，避免部分保存。
- 左侧“收起导航”可收纳为图标栏，主入口仍可点击；再次点击展开，浏览器记住收起状态。保持原有左侧主导航、页面专属上方工具栏和 Teams-inspired 主题。
- 创建/编辑任务与创建子任务时，状态和优先级左右并排；软件版本采用下拉多选，编辑多版本任务时保留全部选择。
- 日志保留“今天计划”“今天实际”，增加独立“明日计划”，保存、读取和备份均包含该内容，年月归档规则不变。
- 日志页面、事项及归档不再显示百分比进度；事项改用“当天完成”勾选框，只记录当天工作，不修改源任务/Issue 状态。历史百分比字段保留以兼容旧数据库，打开新页面不会清空旧值。
- 未完成事项勾选行与已选事项标题不自动换行，长标题省略显示，未完成事项悬停可查看完整标题；原单项/多项拖拽、筛选、去重和保存冲突保护继续保留。

## v3.22.0 历史记录：独立每日日志与年月归档

### 每日记录

- 选择日期，填写“今天计划做什么”和“今天实际做了什么”。每个日期保存一篇个人日志。
- 填写当天整体进度（0–100%），或点击“按事项进度计算”取所选事项进度的平均值。
- 从页面右侧的各项目未完成事项池选择任务/子任务和未关闭 Issue。支持项目筛选与标题/编号搜索。
- 拖拽单个事项到“当天计划事项”；勾选多项后拖拽其中一项可批量加入。也可点击“添加勾选事项”，适用于触屏和键盘。
- 同一事项不会重复加入当天日志；可移除所选事项，填写每项当天进度和工作结果，或标记“当天完成”。
- 日志进度仅描述当天工作，不改变源任务/Issue 的状态。同一事项可在不同日期有独立进度。
- 点击“保存当天日志”持久化；切换日期/页面有未保存提示，关闭网页有离开提醒。
- 左侧按年份和月份归档；可查看全部月份，点击日期重新打开历史日志。只有保存后的日志进入归档。
- 已保存的事项保留项目名、标题、编号与加入时状态快照。原事项改名、完成、删除或项目删除均不会清除历史日志。
- 新增到计划的事项必须仍未完成；若添加后源事项已经完成/删除，保存会保留输入并提示刷新事项列表。
- 同一天多页面编辑以 revision 校验，旧页面保存返回冲突而不覆盖已保存内容；当前输入会保留。

### 数据兼容与结构

启动时自动创建 daily_logs 和 daily_log_items 两张表及索引，原表、原数据和原备份逻辑不变。
数据库备份会一并包含每日计划、实际记录、进度和事项快照。
新模块 daily_logs.py 处理独立 API；static/js/daily_logs.js 处理页面和拖拽。
继续由静态 HTML 加载，无 Node 构建或新增应用运行依赖。

API：GET /api/daily-logs/available 返回跨项目未完成事项；GET /api/daily-logs/archive
返回年月归档；GET /api/daily-logs?year=2026&month=10 支持年月筛选；
GET、PUT /api/daily-logs/YYYY-MM-DD 读取/保存当天日志。
PUT 需要提供最近读取的 revision（新日志为 0），正文 planned/actual、整体 progress，
以及 items（entity_kind、entity_id、progress、result）。快照字段由服务器生成。

## v3.21.0 历史记录：任务依赖与两级 Dashboard

基于 v3.20.0，继续保留模块化静态前端和 Teams-inspired UI。新增功能无需
Node 构建或额外运行依赖，原有项目、任务、Issue、测试、软件版本、研发记录和备份继续可用。

### 任务依赖

- 在任务新建/编辑、子任务创建窗口勾选多个“前置任务”。前置任务全部完成后，后续任务的“等待前置”提示自动解除。
- 依赖表示完成后开始（Finish-to-start），与父子层级分别保存。
- 只允许同一项目中的现有任务；拒绝自己依赖自己、跨项目和直接/间接循环。并发更新同样不能建立循环。
- 任务表新增前置任务及风险列，显示项目内 Task 编号、等待前置、前置延期和日期冲突。
- 前置或间接前置未完成且截止日期早于今天时，标记“前置延期”。
- 前置计划截止日期不早于后续任务计划开始日期时，标记“日期冲突”（按日计算，完成后次日开始）。
- 甘特图显示前置到后续任务的箭头；有依赖风险的箭头/任务条为橙色。没有有效日期的任务仍可保存依赖，但不会绘制相应甘特图箭头。
- 本版采用风险提示方式，不自动修改状态或日期，也不禁止用户手动开始/完成任务。已完成的后续任务不再计入依赖风险。
- 编辑时可取消勾选以清除依赖。删除任务/项目自动清理有关依赖，不删除其他后续任务。
- 部分 PUT 更新未传 dependency_ids 时保留依赖；传空列表明确清空。版本关联和父任务未传时也保留。

### 项目 Dashboard

原总览升级为“项目 Dashboard”。展示完成进度、进行中、延期、今天至 7 天后截止、
等待前置、依赖风险、本周完成、高风险 Issue、测试通过率、任务状态分布和最新记录软件版本。
保留原有待做/已完成任务与高风险 Issue 列表，增加可开始任务、延期、近期截止和依赖风险明细。
点击明细任务可进入对应项目并直接打开任务编辑窗口。

### 个人整体 Dashboard

应用启动默认打开个人 Dashboard，侧边栏和顶部标签都提供入口。
当前应用为单用户本地软件，因此“个人整体”汇总当前数据库中的全部项目，未新增账号系统。
可查看整体指标、各项目进度/延期/风险/版本、跨项目任务及 Issue，并点击进入对应项目和记录。
整体完成进度按全部任务数加权计算，不对项目百分比取简单平均。

### 指标与数据兼容

- 日期指标统一按 UTC+8；延期为未完成且截止日期早于今天，近期截止为今天至今天 +7 天（含两端）。
- 本周以周一为起点。新增 tasks.completed_at 记录任务进入“已完成”的时间；重复保存完成状态保留原时间，重新打开任务会清空，再次完成重新计时。
- 旧版已完成任务的实际完成时间无法确定，迁移后保留空值，不计入“本周完成”，但计入总完成数和进度。
- 测试通过率 = 通过 /（通过 + 失败），未执行和阻塞不进入分母；无通过/失败记录时显示暂无数据。
- “最新记录版本”指最新新增的软件版本记录，不推断是否已正式发布。
- 数据库启动时只新增 task_dependencies 表/索引与 completed_at 字段，保留旧表和已有数据；无需手动执行迁移。

### 关闭浏览器自动退出后台

现在网页会注册客户端会话并每 2 秒发送心跳。

当关闭最后一个 projectmanager 浏览器页面时：

1. 页面通过 `sendBeacon()` 通知后端客户端离开。
2. 后端进入 4 秒宽限期。
3. 如果期间没有页面重新注册，FastAPI / Uvicorn 正常退出。
4. `projectmanager.exe` 进程随之结束。

普通刷新不会导致误退出，因为刷新后的页面会在宽限期内用同一个 session token 重新注册。

如果浏览器异常崩溃或来不及发送关闭通知，后端也会通过心跳超时自动识别失联客户端。
