# projectmanager v2.0

## 运行方式

v2.0 改为：

```text
projectmanager.exe
        ↓
本地 FastAPI 服务
        ↓
自动打开浏览器
        ↓
http://127.0.0.1:8765
```

日常使用仍然只需要双击 EXE。

## 为什么改成 Web UI

网页界面更适合精细控制：

- 表格列宽
- 状态 Badge
- 对齐与间距
- Dashboard
- 响应式布局
- 深色 / 浅色主题
- 后续增加筛选、搜索、拖拽等交互

## 旧数据库继续沿用

继续使用：

```text
robot_project_manager.db
```

把旧数据库放到 EXE 同目录：

```text
projectmanager.exe
robot_project_manager.db
```

即可继续使用原来的：

- 项目
- 任务 / 子任务
- Issue
- 测试
- 软件版本
- 任务 / Issue / 测试的软件版本关联
- 研发日志
- Git 记录
- ROS bag / log

数据库兼容层保留旧字段和旧表，不做破坏性迁移。

## Windows EXE 打包

建议把工程放在短路径，例如：

```text
C:\rpm
```

然后运行：

```bat
build.bat
```

生成：

```text
dist\projectmanager.exe
```

v2.0 已不再依赖 PySide6，因此也避开了之前 Qt 包安装时的超长路径问题。

## 注意

当前服务只监听：

```text
127.0.0.1
```

也就是只允许本机访问，不会对局域网开放。

### 关闭浏览器自动退出后台

现在网页会注册客户端会话并每 2 秒发送心跳。

当关闭最后一个 projectmanager 浏览器页面时：

1. 页面通过 `sendBeacon()` 通知后端客户端离开。
2. 后端进入 4 秒宽限期。
3. 如果期间没有页面重新注册，FastAPI / Uvicorn 正常退出。
4. `projectmanager.exe` 进程随之结束。

普通刷新不会导致误退出，因为刷新后的页面会在宽限期内用同一个 session token 重新注册。

如果浏览器异常崩溃或来不及发送关闭通知，后端也会通过心跳超时自动识别失联客户端。

## v2.9

修复浏览器切换标签页后软件失去响应的问题：

- v2.8 使用 2.5 秒心跳超时判断页面是否关闭。
- 浏览器会对后台标签页的 JavaScript 定时器进行节流，导致正常切换标签页也可能被误判为关闭。
- v2.9 改为：正常关闭主要依赖 `pagehide + sendBeacon`。
- 关闭最后一个页面后仍保留约 **1 秒** 的退出宽限期。
- 心跳改为 15 秒一次，只作为异常浏览器崩溃后的长期兜底。
- 心跳失联阈值扩大到 30 分钟，不会再因普通切换标签页而退出后台。
- 页面从浏览器 BFCache 恢复时会重新注册客户端。
- 每个页面加载使用独立客户端 token，多标签页互不影响。

- 任务列表按父子层级缩进展示，子任务紧跟在父任务下方。

- 默认 Web 端口改为 `7000`，若被占用继续自动尝试 `7001 / 7002 / ...`。
